# V0.5 - 知识库问答

## 目标

对自己的知识库进行 RAG 问答，让积累的知识真正可复用。

---

## 需求拆分

### 需求 0.5.1：本地 Embedding 生成

**描述：** 为所有笔记生成向量嵌入，用于语义搜索

**验收标准：**
- 新笔记创建/更新时自动生成 embedding
- 支持通过 API 生成（OpenAI / Claude）
- 后续可切换为本地模型
- embedding 存储在本地数据库
- 批量生成已有笔记的 embedding

**具体步骤：**
1. 创建 `electron/services/embedding/index.ts` - embedding 服务
2. 创建 `electron/services/embedding/openai.ts` - OpenAI embedding
3. 实现文本分块策略（chunk size 500 tokens，overlap 50）
4. 实现 embedding 生成与存储
5. 实现增量更新（只处理新增/修改的笔记）
6. 创建批量生成任务

**新增数据库表：**
```sql
CREATE TABLE embeddings (
  id TEXT PRIMARY KEY,
  note_id TEXT NOT NULL,
  chunk_index INTEGER NOT NULL,
  chunk_text TEXT NOT NULL,
  embedding BLOB NOT NULL,  -- Float32Array 序列化
  created_at TEXT NOT NULL,
  FOREIGN KEY (note_id) REFERENCES notes(id)
);

CREATE INDEX idx_embeddings_note ON embeddings(note_id);
```

**额外依赖：**
```bash
pnpm add openai  # 如果还没装
# 向量计算
pnpm add ml-distance  # 余弦相似度计算
```

### 需求 0.5.2：向量检索

**描述：** 根据用户问题检索最相关的知识片段

**验收标准：**
- 输入问题，返回 Top-K 相关片段
- 检索速度 < 500ms（本地数据量 < 10000 条）
- 支持设置相似度阈值
- 返回结果包含来源笔记信息

**具体步骤：**
1. 创建 `electron/services/retrieval/index.ts` - 检索服务
2. 实现余弦相似度计算
3. 实现 Top-K 检索（暴力搜索，数据量小时够用）
4. 实现相似度阈值过滤
5. 返回结果附带笔记元信息
6. 后续数据量大时可引入 HNSW 索引

**接口设计：**
```typescript
interface RetrievalResult {
  noteId: string;
  noteTitle: string;
  chunkText: string;
  similarity: number;
  category?: string;
  tags?: string[];
}

interface RetrievalService {
  search(query: string, topK?: number, threshold?: number): Promise<RetrievalResult[]>;
}
```

### 需求 0.5.3：RAG 问答核心逻辑

**描述：** 结合检索结果和大模型，回答用户问题

**验收标准：**
- 用户提问 → 检索相关知识 → 生成回答
- 回答基于用户自己的知识库内容
- 回答附带引用来源（哪篇笔记）
- 无相关知识时明确告知
- 支持多轮对话

**具体步骤：**
1. 创建 `electron/services/rag/index.ts` - RAG 服务
2. 实现 Query → Retrieve → Generate 流程
3. 设计 RAG Prompt（包含检索到的上下文）
4. 实现引用来源标注
5. 实现多轮对话上下文管理
6. 处理无结果情况

**RAG Prompt 模板：**
```
你是用户的个人知识助手。请根据以下知识库内容回答用户的问题。

## 相关知识
{retrieved_chunks}

## 规则
1. 只基于上述知识内容回答，不要编造
2. 如果知识库中没有相关内容，请明确告知
3. 回答末尾标注引用来源

## 用户问题
{user_question}
```
