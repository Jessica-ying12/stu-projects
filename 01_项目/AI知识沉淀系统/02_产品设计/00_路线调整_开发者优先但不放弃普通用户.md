
# 00. 路线调整：开发者优先，但不放弃普通用户

## 1. 为什么要调整路线

你现在的真实使用场景是：

```text
你是开发者
你经常使用命令行
你经常用 Codex CLI
你需要在写代码、排错、问 AI、改项目时调用自己的知识库
```

所以如果第一版只做一个普通桌面客户端，会出现问题：

```text
你在终端里使用 Codex
    ↓
想查以前的经验
    ↓
还要切到客户端搜索
    ↓
复制内容回终端
    ↓
体验割裂
```

因此第一阶段必须支持：

```text
桌面客户端：负责查看、编辑、整理知识
CLI：负责在终端里搜索、提问、导入、给 Codex 提供上下文
```

---

## 2. 调整后的第一目标用户

第一目标用户不是泛泛的“所有 AI 用户”，而是：

> **高频使用 AI 的开发者，尤其是使用 Codex / Claude Code / Cursor / 终端 AI 工具的人。**

原因：

1. 你自己就是这个用户；
2. 需求足够刚性；
3. 使用频率高；
4. 愿意折腾 CLI；
5. Bug 修复、代码方案、命令行上下文非常适合知识沉淀；
6. 可以先用自己真实工作流打磨产品。

但产品长期仍然可以扩展到：

```text
产品经理
运营
学生
职场办公人员
创作者
普通用户
```

---

## 3. 新版产品主线

新版主线是：

```text
本地知识仓库客户端
  +
命令行 aimem CLI
  +
Codex 工作流集成
  +
后续浏览器插件 / IDE 插件 / MCP / 同步
```

不是：

```text
先做一个导入对话工具
```

也不是：

```text
先做浏览器插件
```

而是：

```text
先做一个你自己每天能用的开发者知识仓库。
```

---

## 4. 第一版必须同时满足两个场景

### 场景 A：桌面客户端使用

```text
打开客户端
  ↓
查看知识库
  ↓
编辑笔记
  ↓
右侧 AI 追问当前笔记
  ↓
保存 AI 回答到笔记
```

### 场景 B：命令行使用 Codex 时调用知识库

```bash
aimem search "登录失败"
aimem ask "我之前怎么解决 Next.js hydration 错误？"
aimem context "登录失败 cookie token" --out AIMEM_CONTEXT.md
codex "参考 AIMEM_CONTEXT.md，帮我排查当前项目"
```

或者更顺手：

```bash
aimem codex "帮我排查当前项目登录失败"
```

内部流程：

```text
aimem 检索知识库
  ↓
生成上下文
  ↓
调用 codex
  ↓
可选保存本次 Codex 会话
```

---

## 5. 调整后的版本优先级

之前路线可能是：

```text
客户端 → RAG → 浏览器插件 → CLI
```

现在调整为：

```text
客户端 + CLI 基础 → RAG + Codex 上下文 → Codex 采集 / MCP / IDE → 浏览器插件 → 个人正式版
```

原因：

```text
你用 Codex CLI 多，所以 CLI 不能排太后。
```

---

## 6. V0.1 的新定义

V0.1 不是“普通用户本地手动版”。

V0.1 是：

> **开发者自用 MVP：桌面知识仓库客户端 + aimem CLI 基础 + 当前笔记 AI 对话 + 手动导入 Codex 对话。**

V0.1 要做到：

```text
你可以打开客户端管理笔记
你可以在终端 aimem search 搜索笔记
你可以在终端 aimem ask 提问知识库
你可以把搜索结果输出为 Markdown 给 Codex 用
你可以把一次 Codex 输出保存为知识笔记
```

---

## 7. 先做给你自己用的判断标准

每做一个功能，先问：

```text
我今天用 Codex 写代码时能不能用上？
我遇到报错时能不能马上查到历史经验？
我能不能把这次 Codex 的好答案保存下来？
我下次能不能在终端里调用这条经验？
```

如果答案是不能，这个功能就不是当前优先级。

---

## 8. 不要第一版就做的东西

第一版不要做：

```text
浏览器插件全平台适配
手机端
云同步
团队权限
公共知识市集
漂亮分享页
复杂知识图谱
超级管理员后台
```

这些后面做。

第一版要把你的开发工作流打穿。
