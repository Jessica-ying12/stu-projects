
# 00. 产品重新定位：它到底是什么？

## 1. 之前方向的问题

之前容易把产品理解成：

```text
一个导入 AI 对话的工具
一个自动整理聊天记录的工具
一个采集器
```

但这个理解不够准确。

如果主页面是“导入页”“待整理页”，用户会感觉它只是一个辅助工具，而不是每天都想打开的知识工作台。

真正应该做的是：

> 一个本地优先的 AI 个人知识仓库客户端。

它的重点不是“保存聊天记录”，而是：

```text
把用户和 AI 的对话、网页内容、工作思考、学习内容、问题解决过程，沉淀成可以长期查看、编辑、追问、学习和复用的知识仓库。
```

---

## 2. 新产品定义

推荐定义：

> **AI Knowledge Workspace 是一个本地优先的 AI 知识仓库客户端。用户可以在里面管理自己的知识笔记，并通过右侧 AI 对话栏对当前笔记、当前目录、某个标签或整个知识库继续提问、总结、学习和复用。**

中文一句话：

> **把 AI 对话变成可持续学习和复用的个人知识仓库。**

更通俗的说法：

> 它像 Notion / Obsidian / 语雀，但是内置了一个懂你自己知识库的 AI 助手。

---

## 3. 产品主体验

用户打开客户端后，不应该先看到导入功能，而应该看到自己的知识仓库。

正确主体验：

```text
打开客户端
  ↓
进入知识工作台
  ↓
左边看知识分类、标签、目录
  ↓
中间查看和编辑知识笔记
  ↓
右边和 AI 对当前知识继续对话
```

导入 AI 对话只是一个入口。

浏览器插件、CLI、IDE 插件只是采集和使用扩展。

---

## 4. 产品形态

最终形态不是单个工具，而是一套系统。

```text
普通用户：
  桌面客户端 + 浏览器插件 + 后期手机端

程序员：
  桌面客户端 + CLI + IDE 插件 + MCP Server

团队用户：
  团队知识库 + Web 端 + 权限系统 + 管理后台

平台方：
  超级管理员后台 + 用户/团队/计费/内容/模型管理
```

但第一版不要全做。

第一版只做：

```text
桌面客户端
知识仓库主界面
笔记查看/编辑
右侧 AI 对话栏
模型配置
手动导入
基础搜索
Markdown 导出
```

---

## 5. 这个产品和普通笔记软件的区别

| 对比项   | 普通笔记软件   | AI 知识仓库客户端           |
| ----- | -------- | -------------------- |
| 知识录入  | 用户手动写    | 手动写 + AI 对话整理 + 插件采集 |
| 知识组织  | 用户自己分类   | AI 自动分类 + 用户可调整      |
| 知识使用  | 搜索和阅读    | 搜索 + AI 追问 + 总结 + 学习 |
| 知识复用  | 复制粘贴     | 一键生成模板、周报、PRD、卡片     |
| 上下文   | 单篇笔记     | 当前笔记、目录、标签、全库        |
| 程序员使用 | 很少支持 CLI | 支持 CLI / IDE / MCP   |

---

## 6. 核心价值重新表达

之前的核心价值：

```text
让每一次 AI 问答都不浪费。
```

可以保留，但还不够。

更准确应该是：

```text
让每一次 AI 问答，都进入你的个人知识仓库，并可以被再次学习、追问和复用。
```

最终价值：

1. 保存：不丢失有价值的 AI 对话；
2. 整理：自动变成结构化知识；
3. 学习：根据笔记生成复习、卡片、测试题；
4. 追问：继续问自己的知识库；
5. 复用：生成模板、文档、方案、代码上下文；
6. 迁移：可以导出 Markdown / HTML / PDF / Word；
7. 扩展：程序员可以在 CLI / IDE / AI 编程工具中调用。
