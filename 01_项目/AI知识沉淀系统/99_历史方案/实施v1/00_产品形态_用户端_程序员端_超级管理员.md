# 00. 产品形态：用户用到的到底是什么？

## 1. 最终产品不是单一客户端，而是一套系统

这个产品最终应该长这样：

```text
普通用户看到的是：
  桌面客户端 + 浏览器插件 + 可选手机端

程序员看到的是：
  桌面客户端 + CLI 命令行工具 + IDE 插件 + MCP 服务

企业/团队看到的是：
  团队知识库 + 管理后台 + 权限系统 + 审计日志

平台运营者看到的是：
  超级管理员后台 + 租户管理 + 用户管理 + 模型管理 + 内容/分享管理 + 计费管理
```

产品本质：

> 一个本地优先的 AI 对话知识库中枢，外加多个采集入口和多个使用入口。

## 2. 普通用户使用时是什么样？

### 2.1 第一版用户看到的形态

第一版用户主要使用一个桌面客户端。

名称示例：

- AI Memory Hub
- AI 知识仓
- 对话记忆库
- PromptNote
- AskVault

桌面客户端主界面建议这样设计：

```text
┌──────────────────────────────────────────────────────────────┐
│ AI Memory Hub                                                │
├──────────────┬───────────────────────────────┬───────────────┤
│ 左侧导航      │ 中间列表 / 编辑区               │ 右侧详情        │
│              │                               │               │
│ 首页          │ 待整理对话                      │ 原始对话        │
│ 导入          │ 已整理笔记                      │ 来源信息        │
│ 待整理        │ 搜索结果                        │ 标签/分类       │
│ 知识库        │ Markdown 编辑器                  │ 操作按钮        │
│ 搜索          │                               │               │
│ AI 问答       │                               │               │
│ 导出          │                               │               │
│ 设置          │                               │               │
└──────────────┴───────────────────────────────┴───────────────┘
```

### 2.2 普通用户的典型使用路径

#### 路径 A：手动粘贴

```text
用户复制一段 ChatGPT / Claude / Kimi 对话
    ↓
打开桌面客户端
    ↓
点击「导入」
    ↓
粘贴对话内容
    ↓
选择来源：ChatGPT / Claude / 手动 / 其他
    ↓
点击「保存并整理」
    ↓
系统生成结构化笔记
    ↓
用户确认标题、分类、标签
    ↓
进入知识库
```

#### 路径 B：浏览器插件自动保存

```text
用户在 ChatGPT 网页中对话
    ↓
浏览器插件显示「保存到知识库」按钮
    ↓
点击按钮
    ↓
插件采集当前对话
    ↓
发送到本地客户端
    ↓
客户端进入「待整理」
    ↓
用户确认后生成笔记
```

#### 路径 C：对知识库提问

```text
用户打开「AI 问答」
    ↓
输入：我之前怎么解决登录失败的问题？
    ↓
系统检索本地笔记和原始对话
    ↓
AI 结合用户自己的知识库回答
    ↓
回答附带来源笔记链接
```

## 3. 普通用户实际能用哪些功能？

### 3.1 桌面客户端功能

| 模块 | 用户看到的功能 |
|---|---|
| 导入 | 粘贴对话、导入文件、导入网页文本 |
| 待整理 | 查看新采集内容、批量整理、删除无价值内容 |
| 知识库 | 查看结构化笔记、编辑 Markdown、查看来源 |
| 搜索 | 按关键词、标签、时间、来源搜索 |
| AI 问答 | 对自己的知识库提问 |
| 导出 | 导出 Markdown、HTML、PDF、Word |
| 回顾 | 每日回顾、每周总结、学习卡片 |
| 设置 | 模型配置、数据目录、隐私设置、导出设置 |

### 3.2 浏览器插件功能

| 功能 | 说明 |
|---|---|
| 保存当前对话 | 在 ChatGPT / Claude 等页面点击按钮保存 |
| 自动识别问答 | 提取用户问题和 AI 回答 |
| 采集 URL | 保存来源页面 |
| 发送到本地 App | 通过 localhost 或 Native Messaging 通信 |
| 失败缓存 | 本地 App 没打开时先缓存 |

### 3.3 手机端后期功能

手机端不建议第一版做。后期可以做：

- 查看知识库；
- 搜索笔记；
- 收藏/分享网页到知识库；
- 拍照 OCR 导入；
- 语音记录灵感；
- 查看每日回顾。

## 4. 程序员使用时是什么样？

程序员不只需要桌面客户端，还需要命令行和 IDE 集成。

### 4.1 程序员的核心需求

程序员常见需求：

```text
我之前怎么解决过这个报错？
我之前让 AI 写过某个脚本，在哪里？
我之前总结过某个项目架构，怎么在命令行里直接查？
我正在用 Codex / Claude Code，能不能让它读取我的知识库？
我修 bug 的过程能不能自动保存成笔记？
```

### 4.2 程序员需要一个 CLI：aimem

命令名称示例：

```bash
aimem
```

核心命令：

```bash
# 搜索知识库
aimem search "登录失败"

# 查看某条笔记
aimem show note_123

# 对知识库提问
aimem ask "我之前怎么解决 Next.js hydration 错误？"

# 输出为 JSON，方便脚本处理
aimem search "redis 缓存击穿" --json

# 复制某条笔记到剪贴板
aimem show note_123 --copy

# 导出某条笔记
aimem export note_123 --format md --out ./note.md

# 采集一段终端 AI 会话
aimem run codex

# 启动 MCP 服务，让 AI 编程工具调用知识库
aimem mcp serve
```

## 5. 程序员如何在命令行中调用知识库的某个内容？

### 5.1 方式一：直接搜索

```bash
aimem search "登录失败"
```

输出示例：

```text
找到 3 条相关笔记：

[1] note_20260527_a1  登录失败排查流程
    标签：#bugfix #auth #前端
    摘要：记录了 token 过期、cookie domain、后端 401 的排查方式。

[2] note_20260518_b2  OAuth 回调失败问题
    标签：#OAuth #登录

使用：aimem show note_20260527_a1 查看详情
```

### 5.2 方式二：查看指定笔记

```bash
aimem show note_20260527_a1
```

输出：

```md
# 登录失败排查流程

## 问题现象
用户登录后立刻跳回登录页。

## 原因分析
1. token 写入 cookie 失败；
2. SameSite 配置不正确；
3. 前后端域名不一致；
4. 后端返回 401 但前端未处理。

## 解决方案
...
```

### 5.3 方式三：把知识库内容作为上下文交给其他 CLI AI

```bash
aimem show note_20260527_a1 --plain | codex "根据这条经验，帮我排查当前项目登录失败问题"
```

或者：

```bash
aimem ask "找出我之前解决过的登录失败相关经验，整理成排查清单" --format md > login-debug-checklist.md
```

### 5.4 方式四：通过 MCP 给 Codex / Claude Code / Cursor 使用

后期应该提供 MCP server：

```bash
aimem mcp serve
```

暴露工具：

```text
knowledge_search(query, filters)
knowledge_get(note_id)
knowledge_create_note(content, metadata)
knowledge_recent(limit)
knowledge_add_context(project_path, git_diff)
```

这样 AI 编程助手可以主动调用你的知识库。

### 5.5 方式五：本地 HTTP API

本地客户端启动一个只监听 127.0.0.1 的服务：

```bash
curl "http://127.0.0.1:37891/api/search?q=登录失败"
```

适合脚本、自动化和 IDE 插件调用。

## 6. 超级管理员是什么？

要分两个阶段理解。

### 6.1 个人本地版没有真正的“超级管理员”

如果只是个人本地软件：

```text
用户 = 数据拥有者 = 本地管理员
```

这个阶段只需要「设置中心」，不需要复杂后台。

设置中心包括：

- 数据存储目录；
- 模型 Provider；
- API Key；
- 隐私脱敏；
- 本地加密；
- 导入导出；
- 备份恢复；
- 插件连接状态；
- 本地 API 开关。

### 6.2 云同步 / 团队版开始需要管理员

当你有账号、团队、云同步、分享、社区后，就需要后台角色。

角色建议：

| 角色 | 说明 |
|---|---|
| 个人用户 | 管理自己的知识库 |
| 工作区 Owner | 管理一个团队/组织 |
| 工作区 Admin | 管理成员、权限、知识库配置 |
| 平台 Super Admin | 管理整个 SaaS 平台 |

### 6.3 超级管理员后台功能

超级管理员是你作为平台方使用的后台，不是普通用户使用的。

超级管理员后台要管理：

1. 用户管理；
2. 租户/团队管理；
3. 订阅和计费；
4. 模型调用配置；
5. 系统 Prompt 版本；
6. 分享内容审核；
7. 公共知识市集管理；
8. 存储和同步状态；
9. 异常任务和队列；
10. 审计日志；
11. 功能开关；
12. 系统公告；
13. 数据备份和恢复；
14. 风控与滥用检测。

## 7. 最终用户端产品矩阵

| 端 | 面向谁 | 第一版做吗 | 用途 |
|---|---|---|---|
| 桌面客户端 | 所有人 | 必做 | 知识库核心中枢 |
| 浏览器插件 | 所有人 | 第二版做 | 采集网页 AI 对话 |
| CLI | 程序员 | 第四版做 | 命令行搜索和采集 |
| IDE 插件 | 程序员 | 第四版做 | 采集代码与 AI 修复过程 |
| 手机 App | 普通用户 | 后期做 | 查看、搜索、分享导入 |
| Web 端 | 团队/多端 | 后期做 | 云端访问和团队协作 |
| 管理后台 | 管理员 | 后期做 | 用户、权限、账单、审计 |
| 超级后台 | 平台方 | V3 做 | 平台级运营管理 |
