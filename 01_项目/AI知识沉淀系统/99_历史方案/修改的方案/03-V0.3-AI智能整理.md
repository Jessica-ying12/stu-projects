# V0.3 - AI 智能整理

## 目标

对话自动变成结构化知识笔记，自动分类打标签。

---

## 需求拆分

### 需求 0.3.1：大模型 API 接入层

**描述：** 封装大模型调用，支持多个模型提供商

**验收标准：**
- 支持 Claude API 调用
- 支持 OpenAI API 调用
- 统一的调用接口（切换模型无需改业务代码）
- API Key 安全存储（加密）
- 调用失败自动重试
- 支持配置使用哪个模型

**具体步骤：**
1. 创建 `electron/services/ai/index.ts` - AI 服务统一接口
2. 创建 `electron/services/ai/claude.ts` - Claude API 实现
3. 创建 `electron/services/ai/openai.ts` - OpenAI API 实现
4. 创建 `electron/services/ai/types.ts` - 类型定义
5. 实现 API Key 加密存储（使用 Electron safeStorage）
6. 实现重试逻辑（指数退避）
7. 在设置页面添加 API Key 配置入口

**额外依赖：**
```bash
pnpm add @anthropic-ai/sdk openai
```

**接口设计：**
```typescript
interface AIService {
  summarize(conversation: Conversation): Promise<string>;
  extractTitle(conversation: Conversation): Promise<string>;
  categorize(conversation: Conversation): Promise<string>;
  generateTags(conversation: Conversation): Promise<string[]>;
  generateNote(conversation: Conversation, template: string): Promise<string>;
}
```

### 需求 0.3.2：自动提取标题和摘要

**描述：** 对新导入的对话自动生成标题和摘要

**验收标准：**
- 新对话导入后自动触发标题生成
- 标题简洁准确（10-30 字）
- 摘要概括对话核心内容（50-100 字）
- 生成结果写入数据库
- 生成失败不影响对话保存

**具体步骤：**
1. 创建 `electron/services/processor/title-extractor.ts`
2. 创建 `electron/services/processor/summarizer.ts`
3. 设计 Prompt（标题提取 + 摘要生成）
4. 在对话导入流程中添加处理步骤
5. 实现异步处理队列（不阻塞导入）
6. 更新对话列表展示生成的标题和摘要

**Prompt 设计示例：**
```
你是一个对话整理助手。请根据以下 AI 对话内容：
1. 生成一个简洁的中文标题（10-30字，概括对话主题）
2. 生成一段摘要（50-100字，概括对话的核心问题和结论）

对话内容：
{conversation}

请以 JSON 格式返回：
{"title": "...", "summary": "..."}
```

### 需求 0.3.4：自动打标签

**描述：** 根据对话内容自动生成相关标签

**验收标准：**
- 每个对话自动生成 2-5 个标签
- 标签粒度适中（不过于宽泛也不过于具体）
- 复用已有标签（避免同义标签泛滥）
- 用户可添加/删除标签

**具体步骤：**
1. 创建 `electron/services/processor/tagger.ts`
2. 设计标签生成 Prompt（需要传入已有标签列表以促进复用）
3. 实现标签匹配逻辑（新标签 vs 已有标签）
4. 实现标签写入数据库
5. 在 UI 中展示标签，支持编辑

**Prompt 设计要点：**
- 传入已有标签列表，优先复用
- 限制标签数量 2-5 个
- 标签格式统一（小写、无空格用连字符）

### 需求 0.3.5：结构化笔记生成

**描述：** 根据对话内容和模板，自动生成结构化知识笔记

**验收标准：**

### 需求 0.3.6：处理队列与状态管理

**描述：** 管理 AI 处理任务的队列，避免并发过多

**验收标准：**
- 新对话进入处理队列
- 控制并发数（默认 2）
- 处理进度可查看
- 处理失败可重试
- 不阻塞用户操作

**具体步骤：**
1. 创建 `electron/services/processor/queue.ts` - 任务队列
2. 实现优先级队列（新对话优先）
3. 实现并发控制
4. 实现失败重试（最多 3 次）
5. 添加处理状态到数据库
6. 创建 `src/components/ProcessingStatus.tsx` - 处理状态指示器

**新增数据库表：**
```sql
CREATE TABLE processing_tasks (
  id TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL,
  task_type TEXT NOT NULL,  -- title / summary / category / tags / note
  status TEXT DEFAULT 'pending',  -- pending / processing / completed / failed
  error TEXT,
  created_at TEXT NOT NULL,
  completed_at TEXT,
  retry_count INTEGER DEFAULT 0,
  FOREIGN KEY (conversation_id) REFERENCES conversations(id)
);
```
