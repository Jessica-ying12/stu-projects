# 02. V0.1 本地手动版：桌面客户端

## 1. 版本目标

V0.1 的目标不是做全自动采集，而是验证最核心闭环：

```text
用户粘贴 AI 对话
    ↓
系统保存原始记录
    ↓
AI 自动整理成结构化 Markdown 笔记
    ↓
用户确认
    ↓
进入本地知识库
    ↓
可以搜索和导出
```

一句话：

> 先做一个能用的本地桌面客户端，把 AI 对话变成知识笔记。

---

## 2. 用户最终看到什么

V0.1 用户只需要安装一个桌面客户端。

页面包括：

1. 首页 Dashboard；
2. 导入页；
3. 待整理页；
4. 笔记详情页；
5. 搜索页；
6. 导出页；
7. 设置页。

### 2.1 首页

展示：

- 今日导入数量；
- 待整理数量；
- 已归档笔记数量；
- 最近笔记；
- 常用标签；
- 快捷操作：导入、搜索、设置模型。

### 2.2 导入页

字段：

```text
来源：ChatGPT / Claude / Gemini / Kimi / 手动 / 其他
标题：可选
内容：大文本框
按钮：保存原始记录 / 保存并整理
```

### 2.3 待整理页

展示所有还没整理的对话：

```text
标题 | 来源 | 时间 | 内容长度 | 操作
```

操作：

- 整理；
- 删除；
- 查看原文；
- 批量整理。

### 2.4 笔记详情页

建议三栏：

```text
左：笔记元数据和标签
中：Markdown 笔记编辑器
右：原始对话和来源
```

### 2.5 搜索页

支持：

- 关键词搜索；
- 标题搜索；
- 标签过滤；
- 来源过滤；
- 时间过滤。

### 2.6 设置页

必须有：

- 模型 Provider；
- API Key；
- Base URL；
- Chat Model；
- 数据目录；
- 是否启用脱敏；
- 是否保存原始记录；
- 导出目录。

## 4. 开发实施步骤：从零创建项目

### 4.1 安装基础工具

需要安装：

```text
Node.js LTS
pnpm
Rust
Tauri 依赖
SQLite 客户端，可选
VS Code / Cursor
```

检查：

```bash
node -v
pnpm -v
rustc -V
cargo -V
```

### 4.2 创建 monorepo

```bash
mkdir ai-memory-hub
cd ai-memory-hub
pnpm init
```

创建 `pnpm-workspace.yaml`：

```yaml
packages:
  - "apps/*"
  - "packages/*"
```

创建目录：

```bash
mkdir -p apps packages crates docs migrations scripts
```

### 4.3 创建 Tauri 桌面应用

```bash
cd apps
pnpm create tauri-app desktop
```

建议选择：

```text
Frontend: React
Language: TypeScript
Package manager: pnpm
```

进入项目：

```bash
cd desktop
pnpm install
pnpm tauri dev
```

### 4.4 安装前端依赖

```bash
pnpm add zustand @tanstack/react-query react-router-dom
pnpm add react-markdown remark-gfm
pnpm add clsx tailwind-merge lucide-react
```

安装 Tailwind：

```bash
pnpm add -D tailwindcss postcss autoprefixer
pnpm exec tailwindcss init -p
```

### 4.7 创建数据库迁移

`migrations/0001_init.sql`：

```sql
CREATE TABLE conversations (
  id TEXT PRIMARY KEY,
  source_type TEXT NOT NULL,
  source_name TEXT,
  title TEXT,
  url TEXT,
  status TEXT NOT NULL,
  raw_hash TEXT,
  metadata_json TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE messages (
  id TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL,
  role TEXT NOT NULL,
  content TEXT NOT NULL,
  seq INTEGER NOT NULL,
  metadata_json TEXT,
  created_at TEXT NOT NULL
);

CREATE TABLE notes (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  type TEXT NOT NULL,
  category TEXT,
  summary TEXT,
  body_md TEXT NOT NULL,
  status TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE tags (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  type TEXT NOT NULL
);

CREATE TABLE note_tags (
  note_id TEXT NOT NULL,
  tag_id TEXT NOT NULL,
  PRIMARY KEY(note_id, tag_id)
);

CREATE TABLE note_sources (
  id TEXT PRIMARY KEY,
  note_id TEXT NOT NULL,
  conversation_id TEXT NOT NULL,
  message_id TEXT
);
```

### 4.8 实现 Tauri Commands

需要暴露这些命令给前端：

```rust
#[tauri::command]
async fn create_conversation(input: CreateConversationInput) -> Result<Conversation, String>;

#[tauri::command]
async fn list_conversations(status: Option<String>) -> Result<Vec<Conversation>, String>;

#[tauri::command]
async fn generate_note(conversation_id: String) -> Result<Note, String>;

#[tauri::command]
async fn save_note(input: SaveNoteInput) -> Result<Note, String>;

#[tauri::command]
async fn search_notes(query: String) -> Result<Vec<NoteSearchResult>, String>;

#[tauri::command]
async fn export_note(note_id: String, format: String) -> Result<String, String>;

#[tauri::command]
async fn get_settings() -> Result<AppSettings, String>;

#[tauri::command]
async fn update_settings(input: AppSettings) -> Result<(), String>;
```

### 4.9 前端调用示例

```ts
import { invoke } from '@tauri-apps/api/core'

export async function createConversation(input: CreateConversationInput) {
  return invoke<Conversation>('create_conversation', { input })
}

export async function generateNote(conversationId: string) {
  return invoke<Note>('generate_note', { conversationId })
}
```

## 5. AI 整理 Prompt

### 5.1 系统 Prompt

```text
你是一个个人知识库整理助手。你的任务是把用户与 AI 的原始对话整理成结构化知识笔记。
要求：
1. 保留核心问题、最终结论、可复用方法。
2. 不要编造原文没有的信息。
3. 如果是 bug 或报错，必须提取问题现象、原因分析、解决方案、验证方式、经验沉淀。
4. 如果是产品需求，必须提取背景、用户痛点、方案、流程、风险、后续优化。
5. 输出必须是 JSON，不要输出多余文字。
```

### 5.2 输出格式

```json
{
  "title": "string",
  "type": "qa",
  "category": "string",
  "summary": "string",
  "tags": ["string"],
  "markdown": "# 标题

## 问题
...",
  "needUserConfirm": true
}
```
